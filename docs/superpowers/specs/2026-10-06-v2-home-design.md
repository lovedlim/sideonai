# SideOnAI v2 홈 — 설계 문서

- 날짜: 2026-10-06
- 대상 도메인: `sideonai.com` (홈 `/`)
- 기반: 기존 Next.js 16 (App Router) + React 19 + Tailwind 4 + Vercel 프로젝트 (`sideonai/`)
- 시안: `.superpowers/brainstorm/4904-1791221322/content/neural-core-3d-v2.html` (three.js 실동작 목업)

## 1. 목적

지금의 홈은 링크 모음형 개인 브랜딩 페이지다. v2는 이를 **AI 기업의 원페이지 사이트**로 다시 짠다.

- 첫 화면에서 비주얼로 압도한다. 마우스와 휠에 **즉각** 반응하는 3D 신경망(뉴럴 코어)이 주인공이다.
- 주 방문자는 기업·기관의 교육 담당자이고, 최종 행동은 **협업 문의**다.
- 기존 자산(강연 실적, 도서, 인프런, 학습 도구, 문의 폼)은 버리지 않고 섹션으로 다시 담는다.

### 성공 기준
1. 첫 화면만 보고 "AI 기업"으로 읽힌다 (3D 신경망 + 슬로건).
2. 마우스를 움직이거나 휠을 굴린 뒤 100ms 안에 눈에 보이는 변화가 있다.
3. 스크롤만으로 히어로 → 도메인 장면 → 서비스 → 실적 → 문의까지 끊김 없이 이어진다.
4. 모바일과 저사양 기기에서도 깨지지 않고, WebGL이 없어도 내용은 모두 읽힌다.
5. 기존 링크와 리다이렉트(`/typing`, `/md`, `/code`, `/home`, `/activities`)는 그대로 동작한다.

## 4. 히어로 상세

### 4.1 배치와 스크롤
- 히어로 구간은 높이 `280vh`의 트랙이고, 그 안에서 화면(`100vh`)이 `position: sticky`로 고정된다. **휠을 가로채지 않는다.** 진행도 `p = 스크롤량 / (트랙 높이 − 화면 높이)`, 0~1.
- 데스크톱: 문구는 왼쪽(최대 폭 40%), 구체 중심은 화면 가로 62% 지점. 모바일: 구체가 위, 문구가 아래.

| 진행도 p | 장면 |
|---|---|
| 0.00–0.30 | 히어로. 슬로건·부제·버튼 표시. 0.12부터 흐려져 0.30에 사라짐 |
| 0.30–0.60 | 도메인 장면 진입. 일반 노드는 45% 밝기로 가라앉고, 도메인 노드 6개가 주황으로 커지며 중심과 광선으로 연결. 이름표 등장. 자동 회전이 멈추고 정면 자세로 수렴 |
| 0.60–0.90 | 도메인 장면 유지. 문구 "어떤 도메인에도 AI를 더합니다" 표시 |
| 0.90–1.00 | 전체가 흐려지며 서비스 섹션으로 넘어감 |

- 카메라는 `p`에 따라 `z 3.8 → 3.05`로 다가간다. 구체 전체가 항상 화면 안에 남아야 한다 (이름표가 잘리지 않게).
- 진입 곡선은 ease-out이다. 스크롤을 시작하는 순간부터 움직임이 보여야 한다.

### 4.2 장면 구성
- **그래프**: 3겹 껍질(반지름 1.0 / 0.66 / 0.36)에 노드 520 / 240 / 110개, 총 870개. 각 노드는 가장 가까운 3개와 연결하고, 껍질 사이는 가장 가까운 바깥 노드와 1개씩 잇는다. 시드 고정 난수로 매번 같은 모양.
- **노드**: `THREE.Points` + 셰이더. 가산 혼합, 깊이에 따라 밝기 감쇠.
- **연결선과 신호**: `THREE.LineSegments` + 셰이더. 선의 45%에 빛 점이 선을 따라 달린다.
- **성운**: 점 16,000개. 구형 헤일로 55% + 기울어진 원반 45%. 7%는 주황.
- **에너지 코어**: 중심 구체 + 발광 스프라이트 + 자이로처럼 도는 링 3개. 시안의 하얗게 뭉개진 구체는 **노이즈 플라스마 셰이더**로 바꿔 결이 보이게 한다.
- **블룸**: `UnrealBloomPass` (기본 강도 0.8, 반경 0.6, 임계 0.1). 출력은 선형 색공간 그대로.
- **인트로**: 로드 시 흩어진 입자가 3초에 걸쳐 구체로 모인다. 슬로건은 이에 맞춰 순차 등장.

### 4.3 즉각 반응 (핵심 요구)
| 입력 | 반응 |
|---|---|
| 커서를 구체에 올림 | **생각의 경로**: 커서가 가리키는 바깥 노드에서 중심(AI)까지의 최단 경로가 금색 선과 구슬로 켜지고, 빛이 중심에서 바깥으로 흐름. 중심에 가까운 선부터 30ms 간격으로 차례로 켜지고, 커서나 구체가 움직이면 경로가 따라 바뀜. 도메인 장면에서는 꺼짐 |
| 마우스 이동 | 커서 반경 안의 노드가 바깥으로 13% 부풀고 주황으로 변함(추종 계수 0.45). 구체가 커서 방향으로 회전(계수 0.14). 카메라 시차. 화면상 0.22 이동할 때마다 닿은 지점에서 파문 발생. 커서 주변 발광 원 |
| 스크롤(휠) | 스크롤 속도만큼 "에너지"가 쌓여 노드가 방사형으로 최대 약 30% 터졌다가 복귀(감쇠 2.6/s). 구체에 회전 속도가 더해짐. 신호 속도 최대 약 10배, 블룸 강도 최대 약 2배. 정면에서 파문 발생 |
| 클릭·탭 | 그 지점에서 큰 충격파 |
| 방치 | 3.4초마다 임의 방향에서 자동 충격파 |
| 터치 | 드래그 = 마우스 이동과 동일, 탭 = 클릭과 동일 |

- 파문은 동시에 3개까지(순환 슬롯), 최소 간격 200ms.
- 색 규칙: 신경망·파동·커서 주변은 청록 계열로만 밝아진다. 금색은 생각의 경로와 도메인(광선·표식·이름표)에만 쓴다.
- 구현 중 조정: 파문 진폭과 블룸 부스트는 화면이 하얗게 타지 않도록 초안보다 낮췄다(커서 파문 0.3, 스크롤 파문 0.7, 클릭 1.5, 블룸 +0.3×에너지). 커서 반응 반경은 0.24(화면 높이의 절반 기준)로, 구체 크기에 비례한다.

### 4.4 도메인 장면
- 도메인은 6개: **공공, 금융, 소방, 방송, 교육, 유통**. `src/data/site.ts`에서 바꿀 수 있다.
- **순차 점화**: 여섯 개가 한꺼번에 켜지지 않는다. 도메인 장면 진행도에 따라 번호 순서대로(오른쪽 위부터 시계 방향) 광선이 중심에서 자라나 노드에 닿는 순간 표식이 커졌다 돌아오고 이름표가 켜진다. 식은 `stages.ts`의 `domainReveal`과 셰이더의 `reveal`이 같다.
- 도메인 노드는 정면 반구의 미리 정한 6방향에서 가장 가까운 바깥 노드로 고른다. 정면 자세로 수렴했을 때 이름표가 겹치지 않아야 한다.
- 이름표는 3D 위에 얹은 **HTML 텍스트**다 (19px 굵게, 어두운 알약 배경, 주황 테두리). 중심에는 "AI" 이름표. 장면 모듈이 매 프레임 화면 좌표를 넘기고, 컴포넌트는 React 상태를 거치지 않고 `transform`만 갱신한다.
- 구체 왼쪽 노드의 이름표는 노드 왼쪽에, 오른쪽 노드는 오른쪽에 붙인다.

### 4.5 품질 단계와 대체 화면
| 단계 | 조건 | 구성 |
|---|---|---|
| high | 기본(데스크톱) | 노드 870, 성운 16,000, 블룸 켬, DPR 최대 2 |
| low | 터치 기기, 화면 폭 768px 미만, 논리 코어 4개 이하 중 하나 | 노드 420, 성운 5,000, 블룸 끔, DPR 최대 1.5 |
| static | "동작 줄이기" 설정 또는 WebGL 불가 | 캔버스 없음. 포스터 이미지 + 도메인 6개를 정적 칩으로 표시 |

- high에서 평균 40fps 미만이 2초 이어지면 low로 내린다.
- 히어로가 화면 밖이거나 탭이 가려지면 렌더 루프를 멈춘다.
- three.js는 동적 import로 늦게 불러온다. 그 전까지는 포스터 이미지(`public/images/hero-poster.webp`, 장면을 캡처해 만듦)를 보여주고, 준비되면 교차 페이드한다.

## 5. 아키텍처

3D 장면은 React와 분리한다. 컴포넌트는 입력을 전달하고 이름표만 그린다.

```
src/
  app/
    page.tsx                  섹션 조립 (서버 컴포넌트로 전환)
    layout.tsx                메타데이터·글꼴 갱신
    globals.css               다크 토큰
    activities/page.tsx       색만 다크 토큰으로 교체
  data/site.ts                도메인, 서비스, 도서, 리소스, 링크 (문구의 단일 출처)
  data/activities.ts          강연 목록과 totalCount (activities/page.tsx에서 이동)
  components/
    SiteHeader.tsx  SiteFooter.tsx
    hero/
      NeuralHero.tsx          클라이언트. 스티키 트랙, 입력 수집, 이름표, 품질 판정, 대체 화면
      scene.ts                three.js 장면 생성·갱신·해제
      graph.ts                노드·연결·도메인 노드 생성 (순수 함수)
      stages.ts               진행도 p → 장면 값 변환 (순수 함수)
      quality.ts              기기 조건 → 품질 단계 판정 (순수 함수)
      shaders.ts              GLSL 문자열
    sections/
      Services.tsx  TrackRecord.tsx  Books.tsx  Resources.tsx  Contact.tsx
```

### 인터페이스
```ts
// graph.ts
buildGraph(opts: { seed: number; shells: [count: number, radius: number, jitter: number][]; domainCount: number })
  : { positions: Float32Array; edges: Uint16Array; seeds: Float32Array; domainNodes: number[] }

// stages.ts
stageValues(p: number): { camZ: number; copyOpacity: number; domain: number; domainCopy: number; exit: number }

// quality.ts
pickQuality(env: { reducedMotion: boolean; webgl: boolean; coarsePointer: boolean; width: number; cores: number }): 'high' | 'low' | 'static'

// scene.ts
createHeroScene(canvas: HTMLCanvasElement, opts: { quality: 'high' | 'low'; domainCount: number;
  onFrame(f: { domains: { x: number; y: number; side: 'left' | 'right' }[]; core: { x: number; y: number }; fps: number }): void })
  : { setPointer(nx: number, ny: number): void; setProgress(p: number): void;
      impulse(energy: number, spin: number): void; shockAt(nx: number, ny: number): void;
      resize(w: number, h: number): void; start(): void; stop(): void; dispose(): void }
```

- `scene.ts`만 three.js를 import한다. `NeuralHero`는 `import('./scene')`으로 불러온다.
- `dispose()`는 지오메트리·머티리얼·렌더 타깃·이벤트를 모두 해제한다 (개발 모드 이중 마운트 대비).
- 기존 컴포넌트 처리: `SimpleContactForm`, `RandomBookLink`, `GoogleAnalytics`, `StructuredData`, `ActivityList`는 유지. `ProfileAvatar`, `LinkButton`은 홈에서 더 쓰지 않으면 삭제한다.
- 강연 데이터(`sections`)와 `totalCount`는 `src/data/activities.ts`로 옮긴다. `activities/page.tsx`가 `'use client'`라서 서버 컴포넌트인 홈이 값을 직접 가져올 수 없기 때문이다.

- 섹션 배경에는 WebGL을 쓰지 않는다. CSS만 쓴다.

## 7. 성능·접근성

- three.js와 장면 코드는 초기 번들에 넣지 않는다. LCP 요소는 포스터 이미지와 슬로건이다.
- 슬로건, 부제, 버튼, 도메인명은 모두 실제 HTML 텍스트다. 캔버스는 `aria-hidden`.
- 키보드: 상단 메뉴와 버튼에 보이는 포커스 링. 히어로는 키보드 없이도 스크롤만으로 전부 지나갈 수 있다.
- "동작 줄이기" 설정이면 static 단계로 가고, 카운트업·등장 애니메이션도 끈다.
- 본문 대비는 4.5:1 이상을 지킨다.

## 8. SEO·분석

- `layout.tsx` 메타데이터 설명을 "개인 브랜딩 페이지"에서 기업 소개 문구로 바꾼다. 제목 "SideOnAI - 도메인에 AI를 더하다"는 유지.
- OG 이미지(`public/home-preview.png`)를 새 히어로 캡처로 교체한다.
- `StructuredData`의 설명 문구만 갱신한다. `sitemap.ts`와 `robots.txt`는 그대로.
- 기존 gtag 유틸에 CTA 클릭 이벤트 1종을 추가한다 (히어로 버튼, 상단 메뉴 버튼). 문의 폼 전송 이벤트는 유지.

## 9. 검증

- **단위 테스트** (Vitest 추가): `graph.ts` — 같은 시드면 같은 결과, 노드·연결 수, 연결 인덱스 유효성, 도메인 노드 중복 없음·정면 반구. `stages.ts` — 구간 경계값과 단조성.
- **빌드**: `npm run lint`, `npm run build` 통과.
- **브라우저 확인** (Playwright 스크린샷): 1440×900과 390×844에서 p = 0 / 0.45 / 0.75 / 1 및 각 섹션. "동작 줄이기" 에뮬레이션에서 static 단계. 콘솔 오류 0.
